# Paper experiments — reproduction

One sbatch per paper-evaluation subsection. Each script is
self-contained: it loads `cuda/12.4`, activates the project venv,
runs the relevant bench harness in `benchmarks/bs_kernel/`, and writes
to a stable output directory under `benchmarks/bs_kernel/results/paper-exp/`.

All scripts require an H100 on the `dev` partition of the nano5 SLURM
cluster (account `MST114554`). They also assume the `data/gov_report.jsonl`
dataset is in place — generated by `data/download_dataset.py` if missing.

| sbatch                                  | paper subsection                                          | output directory                                                        | runtime |
|-----------------------------------------|-----------------------------------------------------------|-------------------------------------------------------------------------|---------|
| `exp1a_end_to_end_timing.sbatch`        | End-to-end speedups (timing table, K=64)                  | `benchmarks/bs_kernel/results/paper-exp/exp1_end_to_end/timing/`        | ~55 min |
| `exp1b_end_to_end_strategy.sbatch`      | End-to-end speedups (strategy-mix column, K=64)           | `benchmarks/bs_kernel/results/paper-exp/exp1_end_to_end/trace/`         | ~40 min |
| `exp1c_forced_2l.sbatch`                | Picker-validity check: forced 2L_1POOL vs 2L_DEC_TAIL     | `benchmarks/bs_kernel/results/paper-exp/exp1_end_to_end/forced_2l/`     | ~55 min |
| `exp2_dispatch_ablation.sbatch`         | Dispatch-space ablation (5 forced variants)               | `benchmarks/bs_kernel/results/paper-exp/exp2_dispatch_ablation/`        | ~55 min |
| `exp3_plan_breakdown.sbatch`            | Planning-overhead breakdown (cross-cell + per-step)       | `benchmarks/bs_kernel/results/paper-exp/exp3_plan_breakdown/`           | ~55 min |
| `exp4_long_decode.sbatch`               | Beam search at long decode length                         | `benchmarks/bs_kernel/results/paper-exp/exp4_long_decode/`              | ~40 min |

The dev partition caps single jobs at 60 min, so exp1 ships as three
sub-sbatches (`1a` timing, `1b` strategy mix, `1c` forced-2L sanity);
the trace pass also needs to be a separate job because
`BS_KERNEL_TRACE_PLAN=1` adds `torch.cuda.synchronize()` calls that
inflate `plan_total_ms` and would contaminate the timing numbers.

**DeFT baseline (exp1a, exp4).** DeFT's Triton split-by-node attention
kernel is vendored at `src/beam_engine/baselines/_deft_kernel/`
(copied verbatim from `3rdparty/DeFT/DeFT/deft/layers/attention/
tree_attention.py`; DeFT's own package pins torch==2.5.1 / python>=3.12
so it can't be co-installed in `.venv/`). The bench-side wrapper
`src/beam_engine/baselines/deft.py:DeftBackend` builds DeFT-format
metadata from the page-radix tree we already build for FastTree and
splits per-node readers into BLOCK_M=32 chunks (DeFT's stage-1 kernel
only processes 32 queries per CTA — without the split it would silently
drop overflow at K>32).

**K=64 across exp1 cells.** The original sweep used the scenarios'
natural K (32 for level_system, 16 for the others). At those Ks the
picker chose `SHARED_2L_1POOL` for 100% of steps across every cell,
which made `DEC_TAIL` invisible in the headline table. K=64 doubles
the per-beam tail tile count relative to the (K-packed) root tile,
which is the regime where `DEC_TAIL`'s CTA_Q=1 decode kernel is meant
to dominate. Some 8B cells may OOM at K=64 (especially
multi_chain_reasoning at B=32) — the scripts tolerate per-cell
failures and continue.

## How to run

```bash
# from the repo root
sbatch scripts/paper-exp/exp1a_end_to_end_timing.sbatch
sbatch scripts/paper-exp/exp1b_end_to_end_strategy.sbatch
sbatch scripts/paper-exp/exp1c_forced_2l.sbatch
sbatch scripts/paper-exp/exp2_dispatch_ablation.sbatch
sbatch scripts/paper-exp/exp3_plan_breakdown.sbatch
sbatch scripts/paper-exp/exp4_long_decode.sbatch
```

All six are independent and can be submitted together; SLURM schedules
them as nodes free up.

Logs land in two places:
- The per-experiment log inside the output directory (`expN.log`).
- The SLURM stdout/stderr under `slurm/logs/paper_expN_<jobid>.{out,err}`.

## What each experiment produces

### exp1 — End-to-end speedups (three sbatches)

All three use the same K=64 cells.

- **exp1a_end_to_end_timing.sbatch** — `bs_kernel`, `fasttree`, `deft`, `paged`, `mlca` × six cells, warmup + median of 2.
  CSVs land in `…/exp1_end_to_end/timing/`. The `${model_tag}.csv` files merge the three
  per-scenario CSVs per model.
- **exp1b_end_to_end_strategy.sbatch** — `bs_kernel` only, same six cells,
  `BS_KERNEL_TRACE_PLAN=1`, `--repeat 1`. CSVs land in `…/exp1_end_to_end/trace/`.
  Strategy mix per cell is printed inline in `exp1b.log` (search for "strategy mix:").
- **exp1c_forced_2l.sbatch** — picker validity check. Runs three methods on the
  same six cells: `bs_kernel` (picker free), `bsk_2l_1p` (pinned `SHARED_2L_1POOL`),
  `bsk_2l_dt` (pinned `SHARED_2L_DEC_TAIL`). The picker is correct iff it matches
  whichever of the two forced variants is faster on each cell. CSVs land in
  `…/exp1_end_to_end/forced_2l/`.

### exp2 — Dispatch-space ablation

Runs the long-decode cell (Llama-3.2-1B, K=32, L_p=8192, B=16, max_new=2048)
five times, each forced to a single strategy via the wrappers in
`benchmarks/bs_kernel/bench_batched.py:65-150`:

| method method-name | forced strategy             |
|--------------------|-----------------------------|
| `bs_kernel`        | default picker (free)       |
| `bs_kernel_3l1p`   | `SHARED_3L_1POOL` only      |
| `bs_kernel_4l1p`   | `SHARED_4L_1POOL` only      |
| `bs_kernel_3ldt`   | `SHARED_3L_DEC_TAIL` only   |
| `bs_kernel_4ldt`   | `SHARED_4L_DEC_TAIL` only   |

Output: `…/exp2_dispatch_ablation/merged.csv` with one row per variant.

### exp3 — Planning-overhead breakdown

Two sub-passes inside one job:
- **cross** — six paper-grid cells with `BS_KERNEL_TRACE_PLAN=1 FT_TRACE_PLAN=1`,
  methods restricted to `{bs_kernel, fasttree}`, `--repeat 1`. CSVs land
  in `…/exp3_plan_breakdown/cross/`.
- **substep_{8b,1b}** — the supplementary cells used for the per-step
  sub-breakdown (`pick_ms`, `meta_ms`, `radix_ms`, etc.). The 8B cell is
  K=16/L_p=4096/B=32; the 1B cell is K=32/L_p=8192/B=32. Per-phase
  mean/median/p90/p99/total tables are printed inline in `exp3.log`.

### exp4 — Beam search at long decode length

Same cell as exp2 (Llama-3.2-1B, K=32, L_p=8192, B=16, max_new=2048) but
with all five methods (`paged`, `fasttree`, `deft`, `mlca`, `bs_kernel`).
Mirrors the data behind the "Beam search at long decode length" table
in the paper.

Output: `…/exp4_long_decode/merged.csv` with one row per method.

## Reading the CSVs

Both `bench_sglang_e2e.py` and `bench_batched.py` write CSVs with the same
core columns (plus a few harness-specific extras):

| column                   | what it is                                                              |
|--------------------------|-------------------------------------------------------------------------|
| `decode_total_ms`        | wall time across all decode steps in this run                          |
| `plan_total_ms`          | sum of host-side plan time across all decode steps                     |
| `forward_total_ms`       | sum of attention-kernel time across all decode steps                   |
| `decode_p50_ms`          | per-step median time                                                   |
| `n_decode_steps`         | how many steps the run actually executed (255 for max_new=256)         |
| `method`                 | which backend was used (e.g. `bs_kernel`, `fasttree`)                  |
| `scenario` / `K` / `L_p` | which cell this row measures                                           |

The paper tables in `docs/paper_story.md` quote `decode_total_ms`,
`plan_total_ms`, `forward_total_ms`, and `decode_p50_ms` directly.

## Relationship to `slurm/`

The existing `slurm/bench_*.sbatch` files are kept as development
history; the scripts here are the cleaned-up paper-aligned reproducers
against the same bench harnesses. Either surface produces equivalent
results.
